# personal-brandbook

Этот скилл помогает создать персональный брендбук человека — компактный документ (6-7 страниц A4), который фиксирует позиционирование, аудиторию, фирменные цвета, типографику, голос бренда, ценности и контакты. Итог — аккуратный PDF, который человек использует как опору для сайта, соцсетей, презентаций и деловых предложений.

Главная техническая гарантия скилла: **кириллица в PDF отображается корректно**, без квадратов и «крякозябр». Это обеспечивается встроенными в скилл шрифтами DejaVu (полная поддержка кириллицы) и явной регистрацией шрифтов в обоих движках сборки.

## Когда применять

Запускай скилл, когда человек хочет упаковать свой личный бренд в документ: описать, кто он, для кого работает, как выглядит и звучит его бренд, во что он верит и как с ним связаться. Подходит для экспертов, предпринимателей, коучей, консультантов, блогеров, фрилансеров.

## Рабочий процесс — три шага

Не торопись к PDF. Хороший брендбук рождается из хорошего интервью. Соблюдай порядок: сначала собрать информацию, потом согласовать текст, и только в конце — вёрстка.

### Шаг 1. Сбор информации (интервью по блокам)

Задавай вопросы **по одному блоку за раз**. Не вываливай все вопросы сразу — это перегружает человека и даёт поверхностные ответы. Спроси блок, дождись ответа, при необходимости уточни, переходи к следующему.

Полный список вопросов по шести блокам — в `references/questions.md`. Прочитай этот файл перед стартом интервью и веди человека по нему.

Если человек не знает, что ответить, — не оставляй пустоту. Предложи 2-3 варианта на основе того, что уже о нём знаешь, и помоги сформулировать. Особенно это касается блока визуального стиля: если фирменных цветов нет, предложи палитру под его позиционирование и настроение (строгость, тепло, энергия и т.д.) с конкретными HEX-кодами.

### Шаг 2. Текстовая версия

После интервью собери **полный текст брендбука** по структуре ниже и покажи его человеку целиком в чате. Спроси прямо: «Всё верно? Что поправить?» Дай возможность исправить факты, даты, названия, формулировки. Допускай несколько итераций — не верстай PDF, пока текст не одобрен.

Структура брендбука (7 разделов):

1. **Обложка** — слово «Брендбук», имя, позиционирование одной строкой, год.
2. **Кто я** — биография, проекты, опыт, миссия, слоган.
3. **Целевая аудитория** — 2-3 сегмента, боль и потребность каждого, что их объединяет.
4. **Фирменные цвета** — палитра с HEX/RGB и описанием роли каждого цвета.
5. **Типографика** — шрифт для заголовков и шрифт для текста, где что применять, примеры.
6. **Голос бренда** — тональность, обращение (ты/вы), примеры фраз и анти-примеры (чего бренд не говорит).
7. **Ценности и контакты** — 4-6 ключевых ценностей с пояснением + все ссылки и никнеймы.

### Шаг 3. Оформление в PDF

После одобрения текста собери данные в JSON-файл `brand_spec.json` (структура — в `scripts/brand_spec.example.json`) и собери PDF. Есть два движка, оба с гарантированной кириллицей:

**Движок по умолчанию — reportlab** (`scripts/build_pdf_reportlab.py`). Надёжный, самодостаточный, не требует браузера. Кириллица гарантирована через встроенные шрифты DejaVu. Используй его, если нет уверенности, что в окружении доступен Chromium.

```bash
python scripts/build_pdf_reportlab.py --spec brand_spec.json --output "Брендбук_Имя.pdf"
```

**Движок для богатого дизайна — Chromium/HTML** (`scripts/build_pdf_chromium.py`). Рендерит свёрстанный HTML через настоящий Chromium — лучше для градиентов, сложной сетки, тонкой типографики. Шрифты с кириллицей встраиваются в HTML через `@font-face` (base64), поэтому отображаются корректно независимо от системы. Требует `playwright` + Chromium (см. комментарии в скрипте по установке).

```bash
# 1. Сначала свёрстай HTML на основе assets/brandbook_template.html, подставив контент и цвета.
# 2. Затем отрендери:
python scripts/build_pdf_chromium.py --input brandbook.html --output "Брендбук_Имя.pdf"
```

Рекомендация: по умолчанию используй reportlab (работает всегда). Переходи на Chromium, только если человек хочет более «дизайнерский» вид и движок доступен. Если Chromium не устанавливается — спокойно вернись к reportlab, результат тоже достойный.

## Требования к дизайну PDF

Эти правила уже зашиты в скрипты, но держи их в голове при правках:

Формат A4, книжная ориентация. В оформлении используются фирменные цвета человека. Заголовки разделов — на тёмных (или фирменных) плашках. Между блоками — акцентные линии. Один шрифт для заголовков (с засечками), другой для текста (без засечек). Нижний колонтитул: имя, контакт, номер страницы. На странице «Фирменные цвета» — цветные плашки-образцы с HEX. Ценности — с нумерованными значками. Достаточно воздуха, без перегруза текстом.

## Тон и качество текста

Пиши живым языком, без канцелярита и ИИ-штампов. Не раздувай значимость — конкретно и по делу. Не используй эмодзи в документе. Если человек не может ответить — помоги сформулировать, а не пропускай вопрос.

## Шрифты и кириллица — как это устроено

Скилл несёт собственные шрифты в `assets/fonts/`: `DejaVuSerif`/`DejaVuSerif-Bold` (заголовки) и `DejaVuSans`/`DejaVuSans-Bold` (текст). У них полная поддержка кириллицы. Оба скрипта сначала ищут шрифты в `assets/fonts/`, затем — системные DejaVu, и явно их регистрируют (в reportlab — через `pdfmetrics.registerFont`; в HTML — через `@font-face` с base64). Поэтому в PDF кириллица не превращается в квадраты.

Если человек хочет свои шрифты (например, фирменный шрифт с кириллицей), можно подменить файлы в `assets/fonts/` или передать пути через аргументы скрипта — но новый шрифт обязан содержать кириллические глифы, иначе текст не отрисуется. Латинские шрифты без кириллицы использовать нельзя.

После сборки PDF дай человеку ссылку на скачивание. Если дизайн не понравился — уточни, что именно поменять, и пересобери файл: это можно делать сколько угодно раз.
