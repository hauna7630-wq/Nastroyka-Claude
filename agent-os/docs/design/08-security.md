# 08 — Security Architecture

## Реализовано

| Слой | Механизм |
|---|---|
| Транспорт | TLS везде (Caddy + Let's Encrypt); внутренние сервисы не публикуются наружу (docker-сеть) |
| Изоляция данных | каждая выборка/запись скоупится orgId; агент проверяется на принадлежность org в каждом эндпоинте |
| Инструменты | deny-by-default: http_request — allowlist доменов; code_exec — subprocess-sandbox (rlimits CPU/mem, есть docker-адаптер); per-agent allowlist инструментов |
| Промпты | PII-маскирование перед отправкой в LLM, демаскирование ответа (RegexPiiMasker, карта на run, провайдеру не передаётся) |
| Секреты | GitHub Secrets → ENV контейнеров; в репо секретов нет; OAuth-токен подписки только в ENV |
| Загрузки файлов | cap 30MB, парсер не исполняет содержимое, бинарная эвристика против мусора |
| Аудит | иммутабельный AuditLog на все значимые действия (created/started/retry/hired/plan_fallback...) |
| Сеть LLM | RU-хост ходит в Anthropic только через выделенный US-релей, релей закрыт по IP источника |

## Спроектировано (приоритетный долг)
1. Ротация засвеченного root-пароля RU-хоста + запрет SSH-паролей (ключи only).
2. RBAC: Owner/Admin/Member/Viewer на уровне ControlPlane-методов (матрица:
   найм/промпты — Admin+, retry/DLQ — Admin+, чтение — Viewer+, чат — Member+).
3. Бэкапы: ночной pg_dump в офсайт-хранилище + проверка восстановления.
4. Rate limiting на публичные эндпоинты (Caddy rate_limit).
5. Шифрование at rest (на уровне диска провайдера или pgcrypto для чувствительных полей).
