# 01 — PRD (инженерный, без монетизации)

## Зачем
Личная автономная ИИ-организация: пользователь ставит задачу — команда
типизированных агентов планирует, исполняет, ревьюит и отдаёт атрибутированный
результат; вся история решений персистентна.

## Пользователи
Операционные персоны (Оператор/Строитель/Аналитик/Сисадмин/Agent Runtime) —
см. SYSTEM_DESIGN §2 с JTBD-таблицей.

## Сценарии (реализовано)
1. Личный чат с агентом: память диалога (сервер), вложения файлов, ответ на
   выбранное сообщение, честные ошибки + «Повторить», typewriter.
2. Командная задача: декомпозиция → подзадачи → ревью → доработка; фазы
   НОВАЯ→АНАЛИЗ→В РАБОТЕ→РЕВЬЮ→ДОРАБОТКА→ГОТОВО; «Обсуждение команды».
3. Найм: карточка агента (Команда) или целая команда из каталога (10 шаблонов).
4. Разбор инцидента: Журнал агента + Debug (промпт/шаги/токены) + DLQ requeue.

## Критерий готовности (из ТЗ; выполняется)
Поставить сложную задачу → закрыть вкладку → вернуться: видна полная история
обсуждений, ревью, промежуточных результатов и финал с контекстом (Postgres,
не localStorage). Проверяется в CI E2E на каждом деплое.

## Не-цели
Биллинг/тарифы, публичная регистрация, мульти-регион, маркетинговые метрики.
