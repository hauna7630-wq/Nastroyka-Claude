# 09 — Technical Risks & Failure Modes

Каждый риск: симптом → причина → текущая защита → остаточный риск.

## LLM-слой
1. **Провайдер недоступен / гео-блок** → таймаут или сетевые ошибки CLI →
   релей US + humanizeRunError («провайдер недоступен») + retry-кнопка →
   остаточный: релей — SPOF (план: второй релей, переключение DNS).
2. **Модель отвечает не-JSON планом** → InvalidPlanError → plan_fallback на
   одиночного агента + audit → остаточный: ответ слабее командного.
3. **Пустой/«…» ответ** → EmptyModelOutputError → ретраи → DLQ с честной
   причиной → остаточный: расход попыток на систематически плохом промпте.
4. **Долгий вызов (web-search, много ходов)** → lock 10m, conc=4, UI «думает
   (N мин)» → остаточный: 3-минутный timeout CLI обрывает сверхдлинные задачи
   (план: настраиваемый timeout per-run).

## Очередь/исполнение
5. **Орфаны после redeploy** → раньше «job stalled» → removeOnComplete/Fail +
   отдельное соединение воркера → закрыто.
6. **Двойная доставка** → идемпотентность на всех уровнях (upsert run/step,
   unique чат-ответа, терминальный no-op) → закрыто by-design.
7. **Переполнение очереди** → conc-лимит + статус «в очереди» → остаточный:
   нет приоритетов (план: weight по типу задачи).

## Данные
8. **Рестарт между succeeded и фиксацией ответа в треде** → lazy-backfill из
   Run.output при чтении → закрыто.
9. **Потеря диска хоста** → образы в GHCR + миграции + идемпотентный сид →
   остаточный КРИТИЧНЫЙ: нет офсайт-бэкапа Postgres (история чатов/задач) —
   приоритетная задача из 08-security.
10. **Рост контекста диалога** → бюджеты (12 сообщений / 4000 симв. / клип
    200k на файлы) → остаточный: очень длинные документы теряют хвост (план:
    чанк-саммаризация в long-term память).

## UI/платформа
11. **Кэш браузера/прокси отдаёт старый SPA** → no-store + версионный бейдж
    vNN как индикатор свежести → закрыто операционно.
12. **Ошибка в template literal (backticks/${} / `\s`-эскейпы)** → ломает SPA
    молча → ритуал проверки на каждом деплое + кейс с `\\s` задокументирован →
    остаточный: ручная дисциплина (план: unit-тест на тело шаблона).
13. **Одновременные правки одного агента с двух устройств** → последняя запись
    выигрывает; история промптов сохраняется в PromptVersion → приемлемо для
    личного инструмента.
