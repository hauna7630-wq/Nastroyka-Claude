# 10 — UI Coordinator Architecture

Большая часть этого модуля из нового ТЗ **уже реализована** (вкладка
«Координатор», сайдбар-shell, журнал агента, каталог найма) — ниже помечено
built/designed.

## Назначение
UI Coordinator делает исполнение мульти-агентной системы наблюдаемым в реальном
времени: фазы, обсуждение агентов, журнал, навигация. Источник истины — те же
персистентные Run/Step/ChatMessage; UI — производная, переживающая перезагрузку.

## Подсистемы

### 1. Визуализация фаз — BUILT (v18)
`deriveTeamPhase(parent, children)` → полоса chips
НОВАЯ → АНАЛИЗ → В РАБОТЕ → РЕВЬЮ → ДОРАБОТКА → ГОТОВО (ошибка/нужен-человек —
терминальные). Питается `GET /runs/:id/team`, поллинг 3с до терминала,
восстановление по `agentos_last_task`. Designed-расширение: фазы
PLANNING/DEPLOYMENT/VERIFICATION для задач над кодовой базой (см. doc 11).

### 2. UI обсуждения агентов — BUILT (v18)
Лента «Обсуждение команды»: вклад каждого агента, критика ревьюера (вердикт),
доработка — из child runs. Designed: граф сообщений (узлы=агенты, рёбра=
хэндоффы) поверх существующих `orchestration.subtask`-событий; трекинг решений
per-agent (кто что предложил/отклонил).

### 3. Журнал агента (Admin) — BUILT (v19)
`GET /orgs/:o/agents/:a/runs` + Debug-тумблер: шаги с токенами/латентностью +
превью промпта/вывода. Designed: снапшоты памяти агента на момент шага,
таймлайн-вью с зумом.

### 4. Сайдбар-shell — BUILT (v20)
Персистентная навигация Офис/Задачи/Активность/Сотрудники/Нанять/Команда/Админ,
карточка Координатора (ACTIVE), список сотрудников, переключение разделов (hash).
Designed: переключение рабочих пространств (несколько Org), панель здоровья
системы (очередь/воркеры/Redis/Postgres — из метрик).

### 5. Каталог «Нанять команду» — BUILT (v21)
10 шаблонов, мини-аватары нашим спрайт-движком, идемпотентный найм,
`POST /orgs/:o/teams/:tid/hire`. Designed: drag-and-drop сборка команды,
конфигуратор состава (добавить/убрать роль перед наймом).

### 6. UI Phase Engine (реактивность на шину) — BUILT частично
Офис и граф сборки реагируют на SSE `/runs/:id/events` в реальном времени;
фазы/обсуждение — поллингом `/team`. Designed: единый клиентский редьюсер
событий шины → декларативные обновления визуального состояния (вместо точечных
DOM-патчей), чтобы добавить новые типы событий (CodebaseChangeProposed,
UIEnhancementSuggested) без правки рендера.

## Дополнения к реакциям — BUILT (v23)
Эмодзи-реакции на сообщения (персист в Postgres) — основа для «decision tracking»
(реакция агента/пользователя как лёгкий сигнал согласия/возражения).

## Производительность UI
Canvas-офис: один rAF-цикл, depth-sort, кэш спрайтов, пересоздание буфера на
resize (троттлинг). Designed-бюджет: ≥50 FPS при ≤12 агентах на 2-ядре; LOD
(упрощённые спрайты вдали/при >20 агентов) — см. doc 12.
