# ADR-0001: Использовать Architecture Decision Records

- **Статус:** Принято
- **Дата:** 2026-06-06

## Контекст

По мере роста проекта важные архитектурные решения (выбор технологий, структура модулей, соглашения) забываются, а причины их принятия теряются. Новым участникам трудно понять, почему сделано именно так.

## Решение

Фиксировать значимые архитектурные решения в виде коротких документов — **ADR (Architecture Decision Records)** — в каталоге `docs/architecture/decisions/`.

Каждый ADR:

- нумеруется по порядку: `0001`, `0002`, …;
- имеет статус: `Предложено` → `Принято` / `Отклонено` → при необходимости `Заменено ADR-XXXX`;
- описывает **контекст**, **решение** и **последствия**.

## Шаблон нового ADR

```markdown
# ADR-XXXX: Краткий заголовок решения

- **Статус:** Предложено | Принято | Отклонено | Заменено ADR-YYYY
- **Дата:** ГГГГ-ММ-ДД

## Контекст
Какую проблему решаем и почему сейчас.

## Решение
Что именно решили сделать.

## Последствия
Плюсы, минусы и компромиссы выбранного варианта.
```

## Последствия

- ✅ История решений сохраняется в репозитории рядом с кодом.
- ✅ Новым участникам проще разобраться в причинах.
- ⚠️ Требуется дисциплина — заводить ADR на значимые решения.
