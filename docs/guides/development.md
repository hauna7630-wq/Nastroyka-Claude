# 🛠 Руководство по разработке

## Структура проекта

```
.
├── src/                 Исходный код
│   ├── api.js           Работа с пользователями + кэш + пагинация
│   ├── config.js        Сборка конфигурации
│   ├── queue.js         Очередь задач, счётчики, асинхронные хелперы
│   └── utils.js         Утилиты общего назначения
├── tests/               Тесты (Jest)
│   ├── api.test.js
│   ├── config.test.js
│   ├── utils.test.js
│   └── flaky.test.js    Намеренно нестабильные тесты (демо CI)
├── docs/                Документация (этот каталог)
├── .github/workflows/   CI/CD (GitHub Actions)
└── package.json         Зависимости и npm-скрипты
```

## npm-скрипты

| Скрипт | Команда | Назначение |
|--------|---------|------------|
| `npm test` | `jest` | Запустить все тесты |
| `npm run test:ci` | `jest --ci --coverage` | Прогон для CI с покрытием |

## Рабочий процесс

1. **Создайте ветку** от актуального состояния — см. [git-workflow](../contributing/git-workflow.md).
2. **Внесите изменения** в `src/`.
3. **Добавьте/обновите тесты** в `tests/` — см. [тестирование](./testing.md).
4. **Прогоните тесты локально:** `npm test`.
5. **Закоммитьте** по соглашению о сообщениях коммитов.
6. **Откройте Pull Request** в `main`.

## Добавление нового модуля

1. Создайте файл в `src/`, например `src/payments.js`.
2. Экспортируйте публичные функции через CommonJS:

   ```js
   function charge(amount) {
     // ...
   }
   module.exports = { charge };
   ```

3. Создайте тест `tests/payments.test.js`.
4. При необходимости задокументируйте модуль в [справочнике API](../api/README.md).

## Соглашения

- **Модули:** CommonJS (`require` / `module.exports`).
- **Стиль кода:** см. [code-style](../contributing/code-style.md).
- **Каждая публичная функция** должна быть покрыта тестом.
- **Никаких секретов в коде** — только через переменные окружения.
