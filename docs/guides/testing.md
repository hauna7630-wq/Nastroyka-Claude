# 🧪 Тестирование

Проект использует [Jest](https://jestjs.io/). Тесты лежат в каталоге `tests/` и заканчиваются на `.test.js`.

## Запуск тестов

```bash
# Все тесты
npm test

# Режим CI с покрытием
npm run test:ci

# Конкретный файл
npx jest tests/utils.test.js

# По имени теста (по подстроке)
npx jest -t "formatDate"

# В режиме наблюдения (перезапуск при изменениях)
npx jest --watch
```

## Покрытие кода

```bash
npm run test:ci
```

Отчёт о покрытии будет выведен в консоль; HTML-версия (если включена) — в каталоге `coverage/`.

## Как писать тесты

```js
const { sum } = require('../src/utils');

describe('sum', () => {
  test('складывает два числа', () => {
    expect(sum(2, 3)).toBe(5);
  });

  test('работает с отрицательными', () => {
    expect(sum(-1, 1)).toBe(0);
  });
});
```

### Асинхронные тесты

```js
const { getUser } = require('../src/api');

test('возвращает пользователя по id', async () => {
  const user = await getUser(1);
  expect(user).toMatchObject({ id: 1, name: 'User_1' });
});
```

> В `src/api.js` есть кэш на уровне модуля. Если тесты зависят от его состояния — вызывайте `clearCache()` в `beforeEach`. Аналогично для счётчика в `src/queue.js` есть `resetCounter()`.

```js
const { clearCache } = require('../src/api');

beforeEach(() => clearCache());
```

## ⚠️ Нестабильные (flaky) тесты

Файл `tests/flaky.test.js` содержит **намеренно нестабильные** тесты — они созданы для демонстрации обнаружения «мерцающих» падений в CI. Такие тесты:

- зависят от случайных задержек / времени / порядка выполнения;
- падают не каждый раз, что затрудняет диагностику.

**В рабочем коде так делать не нужно.** Признаки флакающего теста и как их избегать:

| Причина | Решение |
|---------|---------|
| Зависимость от реального времени | Используйте фейковые таймеры: `jest.useFakeTimers()` |
| Случайные значения | Зафиксируйте seed или замокайте `Math.random` |
| Общее состояние между тестами | Сбрасывайте состояние в `beforeEach` |
| Гонки в асинхронном коде | Дожидайтесь промисов через `await`, не полагайтесь на `setTimeout` |

- [ ] Новый код покрыт тестами
- [ ] Нет случайно добавленных нестабильных тестов
- [ ] Тесты не зависят от порядка выполнения
