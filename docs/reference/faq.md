# ❓ Частые вопросы (FAQ)

## Как запустить проект?

Установите зависимости и прогоните тесты:

```bash
npm ci
npm test
```

Подробнее — в [Установке](../getting-started/installation.md) и [Быстром старте](../getting-started/quick-start.md).

## Какая версия Node.js нужна?

18.x или 20.x — именно на них проект проверяется в CI.

## В чём разница между `npm test` и `npm run test:ci`?

- `npm test` — запускает Jest для локальной разработки.
- `npm run test:ci` — добавляет `--ci --coverage`: режим для CI и отчёт о покрытии.

## Почему один тест иногда падает, а иногда нет?

Скорее всего это **нестабильный (flaky)** тест. В проекте есть демонстрационный файл `tests/flaky.test.js` с намеренно нестабильными тестами. Как распознавать и избегать такие — в [руководстве по тестированию](../guides/testing.md#️-нестабильные-flaky-тесты).

## Тесты влияют друг на друга — что делать?

Некоторые модули хранят состояние (`cache` в `api.js`, счётчик в `queue.js`). Сбрасывайте его в `beforeEach`:

```js
const { clearCache } = require('../src/api');
const { resetCounter } = require('../src/queue');

beforeEach(() => {
  clearCache();
  resetCounter();
});
```

## Как добавить новый модуль?

См. раздел «Добавление нового модуля» в [руководстве по разработке](../guides/development.md#добавление-нового-модуля).

## Как настроить параметры (таймаут, размер страницы)?

Через `buildConfig()` — см. [Конфигурацию](../getting-started/configuration.md).

## Куда коммитить изменения?

В рабочую ветку, затем Pull Request в `main`. См. [git-workflow](../contributing/git-workflow.md).

## Где хранить секреты?

В переменных окружения или `.env` (добавленном в `.gitignore`). Никогда — в коде или в репозитории.
