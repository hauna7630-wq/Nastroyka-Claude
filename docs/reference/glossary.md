# 📖 Глоссарий

Краткие определения терминов, встречающихся в документации.

| Термин | Определение |
|--------|-------------|
| **ADR** | Architecture Decision Record — короткий документ, фиксирующий значимое архитектурное решение и его причины. |
| **CI / CD** | Continuous Integration / Continuous Delivery — автоматический прогон тестов и сборок при изменениях кода. |
| **CommonJS** | Модульная система Node.js на основе `require()` и `module.exports`. |
| **Coverage (покрытие)** | Доля кода, исполняемого тестами. |
| **Debounce** | Приём, откладывающий вызов функции до паузы в событиях; повторные вызовы сбрасывают таймер. |
| **Flaky-тест** | Нестабильный тест, который проходит и падает на одном и том же коде из-за случайностей, времени или общего состояния. |
| **Jest** | Фреймворк для тестирования JavaScript, используемый в проекте. |
| **JUnit (отчёт)** | Стандартный XML-формат результатов тестов, понятный CI-системам. |
| **npm ci** | Команда установки зависимостей строго по `package-lock.json`; быстрее и воспроизводимее, чем `npm install`. |
| **Pagination (пагинация)** | Разбиение списка на страницы фиксированного размера. |
| **Pull Request (PR)** | Запрос на вливание изменений из рабочей ветки в основную с возможностью ревью. |
| **SemVer** | Semantic Versioning — схема версий `MAJOR.MINOR.PATCH`. |
| **Состояние на уровне модуля** | Данные, объявленные в области видимости модуля и разделяемые всеми его импортёрами (например, кэш). |

Не нашли термин? Дополните этот файл в рамках Pull Request — см. [участие в разработке](../contributing/CONTRIBUTING.md).
